## 4. How `swing_report.py` works

```
python swing_report.py [-o OUT.html] [--period 5y] [--account 1000] [--risk 0.02]
```
Default output is `swing_report.html`. CI runs `python swing_report.py -o site/index.html` and the script creates the folder if needed. A run takes about 30 seconds locally and about 1 minute in CI.

### 4.1 Pipeline (function names)
1. **`load_prices`** downloads about 5 years of daily OHLCV for `UNIVERSE` (about 97 liquid US tickers) plus SPY, QQQ and ^VIX via yfinance. Any ticker the batch download dropped is retried on its own (ROKU did once).
2. **`indicators`** computes SMA 20/50/200, RSI(2), RSI(14), the prior 20-day high, volume ratio, ATR %, 63-day relative strength vs SPY, and 5-day return.
3. **`SETUPS`** + **`simulate`** run the trade rule: enter at the next open, then exit at **+10% target / −5% stop / after 5 days** (`TARGET, STOP, HOLD`). If target and stop hit on the same bar, the stop is assumed first. Gaps fill at the open.
   Setups: `random` (base rate), `oversold` (RSI2 < 10 and above the 200-day), `momentum` (RS63 > 1.3, above the 20/50-day), `breakout` (close > 20-day high, 1.5× volume, above the 50-day), `highvol` (ATR > 5%), `bigdrop` (−15% in 5 days).
4. **`backtest`** produces overall stats, a split by regime (SPY above/below its 50-day), and per-ticker odds of touching ±10% within 5 days (`up10` / `dn10`).
5. **`selloff_study`** scans SPY's full history for 5-day drops of more than 7% with the VIX above 30 (events at least 30 days apart). It records the next-5-day and next-20-day returns, plus `points` (date, next-week return) for the dot strip.
6. **`screen`** checks which setups fire on the latest bar. **`build_groups`** turns those into watchlist groups, in priority order: Oversold, trend intact → Coin flips (`up10` ≥ 30%) → Selloff bounce → Momentum leader → Breakout. Each group shows up to 8 stocks, and a ticker appears in only one group.
7. **`nyse_holidays`** / **`next_sessions`** work out the next 5-session hold window, using NYSE full-day closures and early closes (Easter computed).
8. **`earnings_dates`** gets the next and last earnings dates (yfinance `get_earnings_dates`, falling back to `.calendar`) for suggested stocks and movers. Flags: `now` = reports inside the hold window; `soon` = within 5 sessions after it; "just reported" = within 14 days.
9. **`day_movers`** finds the top 6 gainers and losers by one-day change. **`fetch_news`** keeps Yahoo headlines from the last 3 days that **name the company** (ticker, cleaned name, or distinctive first word, via `company_keywords`), ranked up for move words and catalyst words and down for boilerplate. **`explain_move`** writes a short reason plus chips: Earnings, move vs SPY, volume ×.
10. **`render`** writes one complete HTML document (section 5).

### 4.2 Tunable constants
`TARGET=0.10, STOP=0.05, HOLD=5, COIN_FLIP_UP10=0.30, GROUP_SIZE=8, SOON_DAYS=5, RECENT_DAYS=14, MOVERS_EACH=6, NEWS_LOOKBACK=3`.
`UNIVERSE` is a hardcoded list near the top of the script. SQ was replaced by **XYZ** (Block's new ticker).

## 5. The page: views, glossary and visuals

### 5.1 Views and navigation
The left menu (a horizontal bar on phones) switches views by `#hash`:
`overview`, `market`, `movers`, `watchlist`, `earnings`, `setups`, `playbook`, `glossary`, `method`.

- Views are `<section data-view="…">`, deliberately **not** `id`, so the browser never auto-scrolls a heading under the sticky phone menu. The script also scrolls to the top on first load.
- `#g-<term>` opens the Glossary scrolled to that term and briefly highlights it.

| View | What it shows |
|---|---|
| Overview | Bottom line; **Market mood at a glance** (VIX gauge + trend pills); coming-up tiles (hold window, earnings in window, top gainer/loser) |
| Market | Trend pills; number tiles; **6-month SPY chart with 50/200-day averages** (+ last-10-sessions table); **fear gauge + 6-month VIX chart**; **selloff dot strip** and its stats |
| Day movers | **One-day change bars** with an SPY reference line; a card per mover with the headline reason, chips and source links |
| Watchlist | Groups of suggested stocks with earnings date, 5-day change and a **↓10%/↑10% odds bar** |
| Earnings | Callout (hold window, holidays, who reports when); **5-week timeline**; full table |
| Setup scoreboard | Outcome-mix bars per setup, target/stop rates, average per trade overall and in the current regime; breakeven math |
| Playbook | Position sizing for the account, max positions, entry timing, exits; PDT/T+1 note |
| Glossary | 51 terms in 8 categories with a search box |
| Method | Data sources, assumptions, limits, how the "why it moved" text is built |

### 5.2 Glossary
- `GLOSSARY` is a list of `(category, id, term, definition, example)` tuples, rendered by `render_glossary()`. The search box `#gloss-filter` filters as you type.
- `q(term_id, label)` creates the small "?" link (`href="#g-<id>"`) placed next to labels. **The id must match a `GLOSSARY` entry.** The check in 9.2 catches broken links.
- Categories: Market and indexes · Price and trend · Indicators · Setups · Backtest and odds · Orders and risk · Earnings and calendar · Report labels.
- Notable entries: VIX with the rule of 16 (VIX ÷ 16 ≈ expected daily move), and **VIX vs the Fear & Greed Index**. The VIX measures only expected volatility, so it's a fear gauge. CNN's 0–100 index combines seven signals, one of which is the VIX.

### 5.3 Chart helpers (plain HTML/CSS + inline SVG, no library)
- **`viz_line`** draws line charts. Paths sit in a 1000×100 SVG viewBox stretched to the plot (`preserveAspectRatio="none"`, non-scaling 2px strokes). Text, dots, gridlines and axis labels are HTML positioned in percent, so they stay crisp at any width. End labels show the value with a line key, and only the first series is labeled if labels would collide. The chart data sits in a `data-d` JSON attribute that the script reads for the crosshair tooltip (hover, tap, arrow keys, Esc).
- **`viz_gauge`** draws the VIX gauge. Zones come from `VIX_ZONES`: calm < 15, normal 15–20, elevated 20–30, fear 30–40, panic 40+. Only the active zone is colored, with its name always in text. The hollow dot marks a week ago.
- **`viz_pills`** / **`trend_state`** show the trend label (Uptrend / Downtrend / Pullback in an uptrend / Recovering) and the distance from the 50- and 200-day averages.
- **`viz_strip`** draws the dot strip of SPY's next-week return per past selloff, stacked to avoid overlaps. It has an average marker and per-dot tooltips.
- **`viz_movers`** draws diverging one-day bars around zero, with value labels at the tips and an SPY reference line.
- **`viz_odds`** draws the mini diverging bar: ↓10% odds to the left, ↑10% to the right (0–50% scale per side).
- **`viz_timeline`** shows earnings dots over the next 35 days, with the hold window shaded, labels stacked into rows, and NYSE closures as diamonds.
- `main()` passes `hist` (the last 126 sessions of SPY close, 50-day, 200-day and VIX) into `ctx`.

### 5.4 Colors (validated, keep them)
Checked with the dataviz skill's `validate_palette.js` against the page's own surfaces, in both themes:
- **Gain/loss marks:** `--gain` teal `#0f7f8c` / `--loss` orange-red `#d4502b` (dark: `#2a9db0` / `#e5673f`). Standard **green/red failed** the colorblind check (ΔE 5.5 deutan), so don't switch back.
- **Text up/down:** `--up` `#0b6e79` / `--down` `#b23c1c` (dark `#5cc4d3` / `#f08a6a`). Signed numbers always carry +/−, so color isn't the only cue.
- **Series:** `--s1` blue, `--s2` orange, `--s3` aqua (passes the all-pairs check). Light-mode aqua is below 3:1 contrast, so lines get direct value labels.
- **Status:** `--good`, `--normal`, `--warning`, `--serious`, `--critical`, always shown with a text label, never color alone.
- All colors are CSS tokens with light values plus dark overrides (both `prefers-color-scheme` and `data-theme`).

## 6. Key findings

### 6.1 Backtest (about 97 stocks, 5 years, about 120k trades)
| Setup | Target hit | Stop hit | Avg/trade | Avg when SPY < 50-day |
|---|---|---|---|---|
| Random (base rate) | 13.7% | 37.6% | +0.16% | +0.29% |
| Oversold in uptrend | 12.3% | 32.8% | +0.43% | +0.20% |
| Momentum leader | 20.4% | 48.2% | +0.21% | +0.28% |
| Breakout + volume | 17.1% | 42.1% | +0.16% | −0.44% |
| High volatility | 25.1% | 56.3% | +0.07% | +0.38% |
| Bounce after −15% in 5d | 27.9% | 58.3% | +0.12% | +0.74% |

No setup has a meaningful edge. Higher odds of +10% come with higher odds of −5%, and returns are before costs. Breakeven with +10/−5 needs the target hit in at least 1/3 of the trades that resolve; the bounce setup sits right at 32%.

## 7. Security model (keep all of this)

**The page (`render`)**
- It's a complete `<!doctype html>` document with a `Content-Security-Policy` meta tag:
  `default-src 'none'; script-src 'sha256-<hash of JS>'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'; object-src 'none'`.
  The hash is computed from the `JS` constant at render time. **Never hardcode it**, because editing `JS` updates it automatically.
- No external resources (system fonts, no CDNs, no chart library). There's one inline script and no inline event handlers. Chart data goes in `data-*` attributes and is parsed with `JSON.parse`.
- Third-party text (headlines, summaries, sources) is always `html.escape`d. Article URLs must be `https://`, and links use `rel="noopener noreferrer nofollow"`.
- Tooltips set their content with `textContent` only, never `innerHTML`.
- `<meta name="referrer" content="no-referrer">` and `robots noindex`.

**Supply chain**
- `requirements.txt` pins exact versions plus SHA-256 hashes. CI installs with `pip install --require-hashes --no-deps -r requirements.txt`.
- **Two-week cooling-off rule:** lock only package versions released at least 2 weeks earlier (see 8.1).
- GitHub Actions are pinned to full commit SHAs (all released at least 4 weeks before 21 Nov 2026):
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1` (v7.0.1)
  - `actions/setup-python@6d4fd22b20465ccc0f7354476588e8df7c9ca0e0` (v7.1.0)
  - `actions/upload-pages-artifact@fc324d3547104276b827a68afc52ff2a11cc49c9` (v5.0.0)
  - `actions/deploy-pages@368f82528645a54fb793d4d04e342629a3f51346` (v5.0.1)
- Workflow: `permissions: {}` at the top. The build job gets `contents: read` only; deploy gets `pages: write` + `id-token: write`. `persist-credentials: false`. Triggers are only `workflow_dispatch` and `schedule`, never `pull_request_target`. No repo secrets exist or are needed.

**Repo settings (applied via `gh api`)**
- Actions: `allowed_actions=selected`, **GitHub-owned actions only**, `verified_allowed=false`, `sha_pinning_required=true`.
- Default `GITHUB_TOKEN` is read-only, and workflows can't approve PRs.
- Workflows from fork PRs by any outside contributor need approval.
- Vulnerability (Dependabot) alerts are on. Pages uses `build_type=workflow`, HTTPS is enforced (http redirects to https, verified).

**The user's side**
- 2FA on the GitHub account matters most, because account takeover is the main remaining risk. **The user confirmed it's enabled (24 Nov 2026).**
- The page is public by URL (free Pages). It contains only market data and the $1,000 sizing example.

## 8. Maintenance procedures

### 8.1 Refresh the dependency lock (every month or two, or after a vulnerability alert)
```bash
# pick a cutoff date about two weeks ago
uv pip compile requirements.in --universal --python-version 3.14 --generate-hashes \
  --exclude-newer <YYYY-MM-DD> -o requirements.txt
uv pip sync --require-hashes --python .venv/bin/python requirements.txt
# confirm it installs on the Linux runner
uv pip install --dry-run --require-hashes --python-platform x86_64-manylinux_2_28 \
  --python-version 3.14 --target /tmp/linuxcheck -r requirements.txt
```
If a pinned version is newer than the cutoff, uv refuses. That's the safety rule working, so loosen the pin in `requirements.in` rather than the cutoff.

### 8.2 Update a pinned action
```bash
curl -fsSL "https://api.github.com/repos/actions/<name>/releases?per_page=4"      # tags + dates; pick one at least 2 weeks old
curl -fsSL -H 'Accept: application/vnd.github.sha' \
  "https://api.github.com/repos/actions/<name>/commits/<tag>"                      # its commit SHA
```
Put the full SHA in `report.yml` with the tag as a comment.

### 8.3 Everyday commands
```bash
.venv/bin/python swing_report.py -o site/index.html && open site/index.html   # build + preview locally
gh workflow run report.yml -R kkrisc/swing-report                              # trigger a refresh
gh run list  -R kkrisc/swing-report --workflow report.yml --limit 3
gh run watch <run-id> -R kkrisc/swing-report --exit-status
gh run view  <run-id> -R kkrisc/swing-report --log-failed
git add <files> && git commit && git push                                       # only after the user approves
```

## 9. Quality checks before showing or pushing a change

### 9.1 Visual review
- Use headless Chrome screenshots: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1280,2000 --screenshot=out.png "file://…/site/index.html#market"`. Add `--blink-settings=preferredColorScheme=1` for light mode.
- **Phone width:** headless Chrome won't make a window narrower than about 500px, so load the page inside a 390px-wide `<iframe>` harness page and screenshot that (with `--allow-file-access-from-files`).
- Look for label collisions, overflow, clipped text, and both themes.

### 9.2 Automated checks (all must pass)
- The script hash inside the CSP matches the sha256 of the `<script>` body, and there's exactly one `<script>`.
- Zero `<link|img|iframe|script|object|embed|use>` tags with `http(s)` `src`/`href`.
- Zero inline `on…=` handlers.
- Every `href="#g-…"` has a matching `id="g-…"`. Every menu link has a matching `data-view`.
- `node --check` passes on the extracted page script.

## 11. Known limitations

- Survivorship bias: the universe was chosen in November 2026 from names that are popular now.
- Backtest returns exclude commissions, spreads and slippage.
- Yahoo data quirks: tickers occasionally drop out (handled with a retry), and future earnings dates are often estimates. The page tells the user to confirm on investor-relations sites.
- Headline-based "why it moved" can be weak. For example, MARA's reason on 20 Nov was an analyst note rather than the bitcoin drop.
- GitHub pauses scheduled workflows after 60 days with no repo activity; a manual run restarts them. Scheduled runs can also be delayed when GitHub is busy.
- The VIX history chart uses the VIX close aligned to SPY trading days (forward-filled).
